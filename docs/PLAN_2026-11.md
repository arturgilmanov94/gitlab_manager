# План доработок по аудиту (ноябрь 2026)

Источник: аудит «Аудит MR Review — ноябрь 2026» (https://claude.ai/artifact/Em79D9imkTsgj3aLj89iBa). Там же разобраны
проблемы C-01…C-32, сценарии A–G, целевые макеты и ответы владельца на вопросы G1–G8. Этот файл — рабочая копия
плана для coding-агента: статус задач отмечается здесь же (`[ ]` → `[x]`), журнал — внизу.

## Принятые решения (не пересматривать без владельца)

| Вопрос | Решение |
| --- | --- |
| G1 | Один git worktree на задачу (issue) для всех этапов: исследование, план, реализация. Рабочую копию владельца (`PROJECT_ROOT`) агенты не используют |
| G2 | Исследование и задача — одна сущность с режимами. Плюс локальные задачи без GitLab issue. Отдельного раздела «Исследования» нет |
| G3 | Одна Claude-сессия на задачу (`--resume`) с ротацией: продолжаем, пока контекст < 50% и сессия свежая, иначе новая сессия с компактным брифом. Поля «Решения» и «Отвергнуто» — сразу. Журнал фактов — позже (T27) |
| G4 | Агент коммитит локально, push запрещён. «Push и draft MR» — одна кнопка владельца с превью и подтверждением |
| G5 | Автоматических запусков (watch-режим, авторевью) нет |
| G6 | Из дашборда: ответ в тред, resolve, approve/unapprove, retry pipeline — с превью текста. Merge — нет |
| G7 | Уведомления в Telegram (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`); без токена функция выключена. Опция «без названий» |
| G8 | Несколько проектов (репозиториев). Переключатель в шапке, выбор запоминается |

## Процесс

- Работа идёт волнами 0 → 1 → 2 → 3. Внутри волны — задачи в порядке зависимостей, коммит на каждую задачу
  (`T05: …`), ветка `main`.
- **После каждой волны — релиз:** `go vet` + `go test ./...` зелёные → проверка волны в Chrome на тестовой копии →
  minor-версия в `VERSION` (волна 0 → 0.30.0, 1 → 0.31.0, 2 → 0.32.0, 3 → 0.33.0; исправления внутри — patch) →
  запись в `CHANGELOG.md` (по-русски, для пользователя) → коммит `0.X.0: …` → тег `v0.X.0` → `git push && git push --tags`
  → пересборка бинарника `mr-review.new`.
- **Перезапуск рабочего дашборда (порт 8765) — только после «ок» владельца.** Агент собирает `mr-review.new`, пишет в
  журнал «готово к перезапуску» и продолжает следующую волну, не дожидаясь.
- Ничего не писать в настоящий GitLab при проверках (никаких «Отправить», reply, resolve, approve на живых MR).
  GitLab в тестах — только `testutil.FakeGitLab`.
