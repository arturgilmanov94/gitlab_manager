# Контракт действий UI

Единый источник правды для кнопок, их названий, приоритета, условий показа и подсказок.
Шаблоны и обработчики пишутся по этому документу; расхождение — баг.

## 0. Общие правила

1. В строке или шапке объекта: **одно primary**, не более **одного secondary**, остальное в меню **⋯**.
2. Primary определяется **состоянием объекта**, а не набором доступных операций.
3. Действие либо доступно, либо **скрыто**, либо disabled **с причиной в подсказке**. Disabled без причины запрещён.
4. Danger-действия (удалить, отменить с потерей, push) — только в ⋯, визуально отделены, с подтверждением там, где теряются данные или пишется во внешнюю систему.
5. Read-only действия (ревью, исследование, разбор CI, проверка замечания) запускаются без подтверждения и сразу дают feedback: «Ревью поставлено в очередь».
6. Внешние ссылки всегда «GitLab ↗» / «Код ↗».
7. Названия описывают **результат**: «Проверить изменения», а не «Verify»; «Открыть результаты», а не «Open».
8. Внутренние термины (`queued`, `stale`, `review_quick`, run id, session id, fingerprint) в UI не показываются; допустимы Git/GitLab-термины: MR, branch, commit, pipeline, diff.
9. Подсказка отвечает на вопрос «что произойдёт после нажатия?» одной фразой.

### Визуальный словарь

| Знак | Цвет | Смысл | Обязательный текст рядом |
|---|---|---|---|
| ✓ | зелёный | успех / актуально / готово | «Проверен», «Готово», «Pipeline passed» |
| ⚠ | жёлтый | требует внимания / устарело | «Есть новые изменения», «Нужен ваш ответ» |
| ✕ | красный | ошибка / блокер | «Ошибка», «Pipeline failed» |
| ● | синий | выполняется | «Проверяется 01:23», «Пишется код» |
| ○ | серый | ещё не выполнялось / неактуально | «Ещё не проверен», «Больше не актуально» |
| — | серый | отменено пользователем | «Отменено» |

Цвет никогда не является единственным носителем смысла.

## 1. Merge Request

Состояние AI-ревью вычисляется отдельно от состояния GitLab и показывается отдельной колонкой/блоком.

| Состояние | Как показано | Primary | Secondary | ⋯ | Скрыто / disabled |
|---|---|---|---|---|---|
| **NEVER** ещё не проверялся | ○ Ещё не проверен | **Запустить ревью** — «AI проверит весь MR на текущем HEAD» | GitLab ↗ | Быстрое ревью · Скопировать ссылку · Убрать из dashboard (danger) | «Проверить изменения» скрыто (нечего сравнивать) |
| **QUEUED / RUNNING** | ● Проверяется · 01:23 | **Открыть прогресс** | GitLab ↗ | Остановить (danger) · История | все запуски ревью скрыты — защита от дубля |
| **WAITING** агент просит разрешение | ⚠ Нужен ваш ответ | **Ответить агенту** (ведёт к блоку разрешения на странице сессии) | GitLab ↗ | Остановить (danger) | как для RUNNING |
| **CURRENT, без открытых** | ✓ Проверен · 0 открытых | **Открыть результаты** | GitLab ↗ | Полное ревью заново · Быстрое ревью · История · Скопировать ссылку · Убрать | «Проверить изменения» disabled: «Нет изменений после последнего ревью» |
| **CURRENT, с findings** | ✓ Проверен · 1 major · 3 minor | **Открыть замечания** | GitLab ↗ | Исправить замечания (только мой MR) · Полное ревью заново · История · Убрать | как выше |
| **STALE** новые коммиты | ⚠ Есть новые изменения · +3 коммита после ревью | **Проверить изменения** — «AI проверит только изменения после последнего ревью и обновит статусы замечаний» | GitLab ↗ | Полное ревью заново · Открыть прошлые результаты · История · Убрать | — |
| **FAILED** | ✕ Ошибка ревью | **Посмотреть ошибку** | **Повторить** — «Запустить то же ревью ещё раз» | Полное ревью · Технический лог · Убрать | — |
| **CANCELLED** | — Отменено · дата | как для предыдущего состояния (NEVER или CURRENT/STALE по последнему успешному ревью) | | | |
| **MR merged / closed** | GitLab: Merged / Closed | **Открыть результаты** (если были) иначе нет primary | GitLab ↗ | Убрать | все запуски скрыты: «MR закрыт» |
| **Draft** | GitLab: Draft | как по состоянию AI | | | ревью доступно, подпись «Draft» рядом |

**Блок GitLab** (список и деталь): ✓/✕/● pipeline · approvals n/m · N unresolved thread · ⚠ behind target by N · Draft · Merged.
Он информационный; действий не имеет, кроме ссылки «GitLab ↗». В детали MR для **моего** MR добавляется агрегат «Что осталось до merge» с одним действием по первому блокеру: «Разобрать ошибку CI» / «Открыть unresolved thread ↗» / «Проверить изменения» / «Готов к merge ↗».

**Быстрое ревью** везде подписано: «Быстрое ревью · только diff, экономит токены» — «AI пройдёт только по diff и обсуждениям, без обхода кодовой базы». Если в проекте есть skill быстрого ревью, подпись дополняется «по правилам проекта».

## 2. Finding (замечание AI-ревью)

Карточка: severity (MAJOR/MINOR/INFO → CRITICAL/HIGH → **major**, MEDIUM → **minor**, LOW/INFO → **info** в UI), заголовок, `файл:строка`, описание, статус, предложение фикса (свёрнуто).

| Статус | Как показано | Primary | Secondary | ⋯ |
|---|---|---|---|---|
| **OPEN** | ○ Нужно проверить | **Проверить замечание** — «AI независимо перепроверит это замечание по актуальному коду» | Код ↗ | Ложное срабатывание · Игнорировать · Отметить решённым · Скопировать текст · Технический вывод |
| **VERIFYING** | ● Проверяется | — | Код ↗ | Остановить |
| **CONFIRMED** | ✓ Подтверждено | **Исправить** (только мой MR; добавляет в выбор «Исправить замечания») | Код ↗ | Ложное срабатывание · Игнорировать · Отметить решённым · Скопировать |
| **FALSE_POSITIVE** | ✕ Ложное срабатывание (приглушено) | — | Код ↗ | Вернуть в открытые · Скопировать |
| **RESOLVED** | ✓ Исправлено | — | Код ↗ | Вернуть в открытые |
| **OBSOLETE** | ○ Больше не актуально | — | — | Скопировать |
| **IGNORED** | — Игнорируется (приглушено) | — | — | Вернуть в открытые |
| **UNCLEAR** | ? Недостаточно данных | **Проверить замечание** повторно | Код ↗ | Ложное срабатывание · Игнорировать |

После инкрементального ревью карточки группируются: **Новые** · **Всё ещё есть** · **Исправлены** · **Неактуальны**.

Реализовано в 0.6.0: строка замечания с ⋯ → «Код ↗» (файл в GitLab на проверенном коммите), «Скопировать текст»,
для OPEN — «Ложное срабатывание» · «Игнорировать» · «Отметить решённым», для ручных статусов — «Вернуть в открытые».
Описание и предлагаемый фикс рендерятся как markdown; упоминания `файл:строка` — ссылки. «Проверить замечание» — не реализовано.

## 4. Сессия (запуск агента любого типа)

| Состояние | Как показано | Primary | Secondary | ⋯ |
|---|---|---|---|---|
| **QUEUED** | ○ В очереди | Открыть | — | Остановить |
| **RUNNING** | ● Выполняется · этап · 08:42 | **Открыть** | — | Остановить (danger) |
| **WAITING_FOR_USER** | ⚠ Нужен ваш ответ | **Ответить** | Открыть | Остановить |
| **DONE** | ✓ Завершена · 03:46 | **Результат** | Продолжить сессию | Технический лог · Повторить |
| **FAILED** | ✕ Ошибка | **Посмотреть ошибку** | **Повторить** | Технический лог |
| **CANCELLED** | — Остановлена | Результат частичный (если есть) | Повторить | Технический лог |

Название сессии = объект + тип: «!113579 · Ревью», «EU-11477 · Решение задачи», «!113571 · Исправление CI».
В карточке сессии всегда виден **контекст**: «Новая сессия» или «Продолжение сессии #N (ревью !113632 · 6.6M токенов)».

### Замечание (finding) на странице MR и сессии

| Состояние | Как показано | ⋯ |
|---|---|---|
| **OPEN** | статус «открыто» | **Проверить замечание** (второе мнение отдельным read-only запуском) · Код ↗ · Скопировать · Ложное срабатывание · Игнорировать · Отметить решённым |
| **OPEN + проверено: подтверждено** | «открыто» + строка «подтверждено агентом · проверка #N» с доказательством | как для OPEN (повторная проверка возможна) |
| **OPEN + проверено: недостаточно данных** | «открыто» + «недостаточно данных · проверка #N» | как для OPEN |
| **FALSE_POSITIVE / OBSOLETE (по проверке)** | «ложное срабатывание» / «неактуально» + «проверка #N» с доказательством | Код ↗ · Скопировать · Вернуть в открытые |
| **FIXED / RESOLVED / IGNORED** | как раньше | как раньше |

Проверки замечаний не меняют состояние AI-ревью MR в списке и могут идти параллельно (по одному запуску на замечание);
полное ревью или проверка изменений в это время не стартуют («уже выполняется #N»).

### Выбор контекста перед запуском (Phase C)

На страницах MR и задачи в блоке «Агент для запусков» — список **Контекст**: «Новый чат · пустой контекст» (по умолчанию) и
«Продолжить сессию #N · тип · агент · токены · когда» для каждой подходящей сессии. Подходящая = завершённая, с сохранённым
идентификатором сессии, из того же каталога, что и новый запуск: ревью и исследование — корень проекта; решение задачи —
workspace ветки; исправление замечаний — workspace ветки MR (пока продолжается только из формы, без списка). Опция несёт
`data-kinds`: если выбрана сессия другого действия, кнопка не запускает ничего и показывает подсказку. Сессия продолжается
тем же агентом, что её начал; переключатель агента в этом случае не действует. Если сессий нет — подсказка «пока нет
завершённых сессий с сохранённым контекстом»; Codex и Cursor могут не вернуть идентификатор — тогда доступен только новый чат.
В строках списков MR и задач бейдж **контекст #N** ведёт к этому списку. На странице «Сессии» запуски одной сессии показаны
цепочкой «сессия: #1 → #5». Запуски из списков всегда стартуют новым чатом (кроме «Проверить изменения», которое продолжает
сессию ревью само).

### Страница сессии
- Сверху: этапы ✓ ● ○ (Подготовка workspace → Анализ → План → Реализация «работаю с: файл» → Тесты → Self-review → Результат) и elapsed. Без процентов. Реализовано пока как строка «сейчас: <последний вызов инструмента>».
- При `WAITING_FOR_USER`: крупный блок «НУЖЕН ВАШ ОТВЕТ» с вопросом, вариантами и свободным полем; `Ответить` продолжает **ту же** сессию.
  Реализованный вариант — **запрос разрешения** (как в терминале): инструмент, ввод, причина, предложенные агентом правила;
  действия «Разрешить» · «Разрешить и не спрашивать в этой сессии» (только если агент предложил правила) · «Отклонить» с комментарием агенту.
  Подсказка на каждой кнопке объясняет последствия. Без ответа запрос истекает и считается отклонённым (подпись под кнопками).
- После завершения: блок «Разрешения в этой сессии» — все запросы с решениями и вызовы, отклонённые автоматически по правилам.
- У плана: **Сохранить план в проект** — markdown в каталог планов проекта; после сохранения показан путь и «скопировать путь».
- Ошибка: человекочитаемый заголовок + `Повторить` + `Технический лог`.
- «Технический лог», «Что было передано агенту», «Результат (JSON)» — свёрнуты внизу.

## 5. Workspace (worktree агента)

| Состояние | Как показано | Primary | ⋯ |
|---|---|---|---|
| **ACTIVE** сессия работает | ● Агент работает | **Открыть сессию** | — |
| **DIRTY** есть незакоммиченное | ⚠ Есть незакоммиченные изменения | **Показать diff** | Подготовить MR · Скопировать путь · Удалить workspace (danger, confirm: «изменения будут потеряны») |
| **CLEAN** закоммичено, не запушено | ○ Закоммичено, не отправлено | **Подготовить MR** | Показать коммиты · Скопировать путь · Удалить workspace (confirm) |
| **PUSHED** | ✓ Отправлено в origin | **Открыть MR** / **Создать MR** | Скопировать путь · Удалить workspace |
| **GONE** каталог удалён | — Удалён, ветка сохранена | — | Убрать из списка |

Никаких «Open terminal / Open IDE». Основная рабочая копия пользователя не трогается.

## 7. Обзор (action inbox)

Порядок блока «Нужно от меня»: 1) нужен ответ агенту → 2) упавший pipeline моего MR → 3) новые коммиты после ревью → 4) ревью с ошибкой → 5) мой MR готов к merge → 6) информационное.

| Элемент | Текст | Primary |
|---|---|---|
| Сессия ждёт ответа | ⚠ EU-11477 · Агенту нужен ответ · «…вопрос…» | Ответить |
| Мой MR, pipeline failed | ✕ !113571 · Pipeline failed · 2 failed jobs | Разобрать ошибку |
| MR stale | ⚠ !113477 · +3 коммита после ревью | Проверить изменения |
| Ревью с ошибкой | ✕ !113579 · Ревью не удалось | Повторить |
| Мой MR готов | ✓ !113579 · Все проверки пройдены, MR готов к merge | Открыть MR ↗ |
| Новый MR на ревью | ○ !113632 · Ещё не проверен | Запустить ревью |

Блок «Агенты»: активные сессии с этапом и elapsed, действие «Открыть». Блок «Мои MR»: счётчики Ready to merge · Waiting review · Needs changes · Failed pipeline, клик — фильтр списка MR.
Пустое состояние: «Сейчас ничего не требует вашего внимания».

## 9. Фильтры и поиск

Поиск по номеру, названию, автору, ветке (поле «Фильтр», запоминается на вкладке). Под панелью — фасетные фильтры-чипы,
состояние хранится в браузере на каждую страницу (localStorage) и переживает перезапуск:

| Список | Группы чипов | Семантика |
|---|---|---|
| Merge requests, История | Мои · Чужие; Готовые (без Draft) · Draft; Ещё не проверены · Новые изменения · Проверены · Выполняется · Ошибки; метки (`HIGHLIGHT_LABELS`) | внутри группы одиночный выбор, метки — «любая из выбранных»; группы объединяются по И |
| Задачи | метки | то же |
| Сессии | Активные · Нужен ответ · Завершённые · Ошибки · Остановленные | одиночный выбор |

Активные чипы подсвечены, рядом «N из M» и «Сбросить». Если под фильтр ничего не подходит — строка «Под фильтр ничего не подходит · Сбросить фильтры»
вместо пустой таблицы. «Требуют внимания» как сохранённый фильтр не делается: этот срез — экран «Обзор».

### Метки GitLab

Метки из `HIGHLIGHT_LABELS` (по умолчанию `high` красным, `product` жёлтым, `bug` оранжевым) показываются бейджами в строке MR и задачи и в шапке их страниц;
регистр метки в GitLab не важен. Остальные метки у задач остаются серым текстом, у MR не показываются вовсе — чтобы строка не разъезжалась.
