# UX-аудит текущего интерфейса (версия 0.2.2)

Цель аудита: зафиксировать, что сейчас видит пользователь на каждом экране, какие действия ему предлагаются,
где интерфейс требует знания внутренней логики, и чем это заменяется. Контракт новых действий — в
[UX_ACTIONS.md](UX_ACTIONS.md). План внедрения — в [ROADMAP.md](ROADMAP.md).

Критерий оценки везде один: **может ли пользователь, не зная архитектуры dashboard, за несколько секунд понять
состояние объекта и следующее разумное действие?**

Обозначения проблем: 🔴 мешает понять состояние или действие · 🟠 заставляет вспоминать внутреннюю логику · 🟡 косметика/непоследовательность.

## 1. Экраны и маршруты сейчас

| Экран | Маршрут | Назначение сегодня |
|---|---|---|
| Список MR | `/` | все MR, где я reviewer/assignee/author, с последним запуском и кнопками запуска |
| Деталь MR | `/mr/{id}` | панель запуска (агент, 3 вида ревью, исправление замечаний), последний результат, история |
| Список задач | `/issues` | задачи GitLab с последним запуском и кнопками План / Реализовать |
| Деталь задачи | `/issue/{id}` | описание, панель запуска (агент, указания, ветка, План / Реализовать), история |
| Запуск | `/run/{id}` | статус, результат (findings / план / отчёт), worktree и git-действия, вопрос агенту, лог, промпт, JSON |
| Doctor | `/doctor` | проверка окружения |
| Навигация | шапка | Merge requests · Задачи · Doctor |

Нет экранов: Обзор (что требует внимания), Сессии (все запуски), CI, Workspaces.

## 2. Список MR (`/`)

**Что показано:** MR, название + автор + бейджи «мой» / «N обсужд.», ветки, head SHA + «новые коммиты», последний запуск
(статус, тип, агент, вердикт, дата), число открытых замечаний, кнопки.

**Действия в строке:** `Быстрое` · `Полное` · `Проверить` · `GitLab ↗` — четыре кнопки одинакового веса, одна из них синяя.
Над таблицей: `Добавить`, `Синхронизировать с GitLab`. Под таблицей: переключатель агента.

| Проблема | Оценка | Замена |
|---|---|---|
| Кнопки «Быстрое» и «Полное» не называют объект действия; «Проверить» вообще непонятно что проверяет | 🔴 | одно primary по состоянию: «Запустить ревью» / «Проверить изменения» / «Открыть замечания»; «Быстрое ревью · только diff» и «Полное ревью» в ⋯ |
| Четыре равновесные кнопки в каждой строке; нет иерархии | 🔴 | `[primary] [GitLab ↗] [⋯]` |
| Состояние AI-ревью не выделено как состояние: «новые коммиты» — мелкий жёлтый текст под SHA, «—» если не проверялся | 🔴 | колонка «AI review» с ✓ ⚠ ● ○ ✕ и текстом: «Проверен», «Есть новые изменения (+3)», «Проверяется 01:23», «Ещё не проверен», «Ошибка» |
| Статус GitLab (pipeline, approvals, threads, draft) не показан вовсе, только «opened» | 🔴 | колонка «GitLab»: ✓ pipeline · approvals n/m · N thread · draft/merged |
| «Проверить» disabled без причины, когда ревью не было | 🟠 | скрыто, пока нечего проверять; при активном запуске вместо кнопок — «Открыть прогресс» |
| «Открыто» показывает «—» для непроверенных и число для проверенных — колонка читается как что-то отдельное от AI-ревью | 🟠 | findings в колонке AI review: «1 major · 2 minor» |
| Переключатель агента внизу страницы оторван от строк; неочевидно, что он влияет на кнопки в таблице | 🟠 | выбор агента в диалоге запуска/⋯ и в деталях; глобальный по умолчанию — в настройках |
| Вердикт «Ок с замечаниями» показывается даже когда ревью устарело — старый вердикт можно принять за актуальный | 🔴 | при stale вердикт приглушён и подписан «по коммиту a82f01c» |
| Нет фильтров и поиска; при 20+ MR список читается плохо | 🟠 | поиск + фильтры: Требуют внимания · Нужно ревью · Мои · Выполняется · Ошибки · Готовые · Draft |
| «Синхронизировать с GitLab» перегружает страницу целиком, после чего теряется позиция | 🟡 | обновлять таблицу без перезагрузки, тост «Синхронизировано N» |
| Внутренние подписи в подсказках упоминают «read-only», «glab api», «head SHA» | 🟡 | подсказки в терминах результата: «AI проверит только изменения после последнего ревью» |

## 3. Деталь MR (`/mr/{id}`)

**Что показано:** шапка (автор, ветки, head, обсуждения, даты), панель «Агент / Ревью / Мой MR» с кнопками
`Быстрое ревью` · `Полное ревью` · `Проверить исправления` · `Исправить замечания ревьюеров (N)` + поле уточнений,
прогресс активного запуска, предупреждение о новых коммитах, последний результат с таблицей findings и обсуждений,
история запусков.

| Проблема | Оценка | Замена |
|---|---|---|
| Три кнопки ревью одинаковые по весу; какая нужна сейчас — решает пользователь | 🔴 | primary по состоянию + ⋯ с остальными |
| «Проверить исправления» — непонятно чьи исправления; на деле это проверка старых findings на новом head | 🔴 | «Проверить изменения» с подписью «что изменилось: a82f01c → cf648b2, +3 коммита» |
| Статус GitLab и статус AI смешаны в одной строке метаданных | 🔴 | два отдельных блока «GitLab» и «AI review» |
| Нет «что изменилось» между ревью и head (коммиты, +/-) | 🔴 | блок «Изменилось: +3 commits, +153 −23» |
| Таблица findings: нет действий у отдельного замечания, нельзя отметить ложное / проверить одно | 🔴 | карточки findings с `Проверить замечание` · `Код ↗` · ⋯ (ложное, игнорировать, решено, копировать) |
| Вердикт и summary старого ревью показываются как «Последний результат» даже при новых коммитах | 🔴 | заголовок «Проверено на a82f01c · есть новые изменения», приглушённый стиль |
| «Убрать» и «Обновить из GitLab» рядом с primary в шапке | 🟡 | «Обновить» остаётся вторичным; «Убрать» — в ⋯ как danger |
| Поле «уточнения для агента» видно всегда, даже когда исправлять нечего | 🟡 | появляется в диалоге «Исправить замечания» |
| Вопрос агенту доступен только со страницы запуска | 🟠 | ссылка «Продолжить сессию» из блока результата |

## 4. Список задач (`/issues`)

**Действия в строке:** `План` · `Реализовать…` · `GitLab ↗`.

| Проблема | Оценка | Замена |
|---|---|---|
| Нет состояния задачи; видно только «последний запуск: отменён · План · claude» — что с задачей, непонятно | 🔴 | человеческий статус: «Новая», «Есть план», «Пишется код», «Нужен ваш ответ», «Готово к MR», «Ошибка» |
| «План» и «Реализовать…» не говорят, что произойдёт («…» намекает на форму) | 🟠 | «Решить задачу» (primary) · «Исследовать» (secondary); после исследования primary = «Реализовать этот план» |
| Метки GitLab свалены строкой («Product, To Do, MP::Bukhanov…») | 🟡 | бейджи, не более 3 + «+N» |
| Отменённые запуски выглядят как ошибка (серый круг с минусом), хотя это действие пользователя | 🟡 | «Отменена вами» с датой; в статусе задачи не учитывается |
| Таблица вылезала за карточку (исправлено в 0.2.2) | ✓ | — |

## 5. Деталь задачи (`/issue/{id}`)

| Проблема | Оценка | Замена |
|---|---|---|
| Результат плана не связан с реализацией: план надо копировать в «Указания» руками | 🔴 | после исследования кнопка «Реализовать этот план» передаёт план автоматически |
| Поле ветки и «от origin/develop, в отдельном worktree» — технические детали в основной форме | 🟠 | ветка по умолчанию скрыта в «Дополнительно» |
| Нет статуса задачи и её истории как единого процесса (исследование → реализация → MR) | 🔴 | лента этапов задачи + текущее состояние |
| Описание задачи свёрнуто по умолчанию | 🟡 | первые строки видны, «Показать полностью» |

## 6. Страница запуска (`/run/{id}`)

| Проблема | Оценка | Замена |
|---|---|---|
| Пока запуск идёт, главное на экране — хвост raw-лога | 🔴 | структурный прогресс: этапы ✓ ● ○ и «работаю с: файл», elapsed; лог — отдельно «Технический лог» |
| При ошибке показывается текст исключения/stderr как есть | 🔴 | «Не удалось выполнить ревью: Claude завершился с ошибкой» + `Повторить` + `Технический лог` |
| Кнопки `Commit` · `Push` · `Создать MR` · `Удалить worktree` в одном ряду, danger не отделён | 🟠 | «Подготовить MR» как primary с чек-листом; Push/Создать MR внутри формы с подтверждением; «Удалить workspace» в ⋯ |
| «Создать MR» использует два браузерных `prompt()` | 🟠 | форма: заголовок, описание, что проверено, ограничения |
| Не видно, новая это сессия или продолжение, и чем она заполнена | 🔴 | блок «Контекст: новая сессия» / «продолжение сессии #N · 6.6M токенов · ревью !113632» |
| Вопрос агенту внизу страницы, не выделен | 🟠 | «Продолжить сессию» выше лога; при `waiting_for_user` — крупный блок «Нужен ваш ответ» |
| Вкладка «Промпт» называет себя «только добавления dashboard» — внутренний термин | 🟡 | «Что было передано агенту» |

## 7. Навигация, состояния, общее

| Проблема | Оценка | Замена |
|---|---|---|
| Нет домашнего экрана «что требует внимания» — пользователь сканирует таблицы сам | 🔴 | Обзор: «Нужно от меня» / «Агенты» / «Мои MR» |
| Запуски разбросаны по MR и задачам; нет одного места, где видно всё, что делают агенты | 🔴 | Сессии |
| Worktree видны только со страницы запуска | 🟠 | Workspaces |
| CI не представлен вовсе | 🔴 | CI |
| Doctor — вкладка первого уровня, хотя нужен раз в месяц | 🟡 | в подвал / меню |
| Статусы запусков переведены (✓), но статуса «нужен ответ» нет | 🔴 | `waiting_for_user` → «Нужен ваш ответ» |
| Обновление страниц перезагрузкой — теряется скролл и фокус | 🟡 | точечное обновление блоков |
| Подсказки хорошие, но длинные (5–7 строк) | 🟡 | одна фраза «что произойдёт»; детали — по «подробнее» |
| Тема только светлая, узкие окна ломают шапку и панели действий | 🟡 | фаза D |

## 8. Сводная таблица переименований

| Было | Стало | Где |
|---|---|---|
| Быстрое / Быстрое ревью | Быстрое ревью · *только diff, экономит токены* | ⋯ у MR |
| Полное / Полное ревью | Полное ревью · *заново весь MR на текущем HEAD* | ⋯ (или primary при NEVER, если пользователь выбрал полный режим) |
| Проверить / Проверить исправления | Проверить изменения · *только изменения после последнего ревью* | primary при STALE |
| — | Запустить ревью | primary при NEVER |
| — | Открыть результаты / Открыть замечания | primary при CURRENT |
| — | Открыть прогресс | primary при RUNNING |
| — | Посмотреть ошибку · Повторить | FAILED |
| Исправить замечания ревьюеров | Исправить замечания · *выбранные findings и обсуждения, в отдельном workspace* | мои MR |
| — | Проверить замечание | у каждого finding |
| План / Составить план | Исследовать | задачи |
| Реализовать… / Реализовать в worktree | Решить задачу | задачи |
| — | Реализовать этот план | после исследования |
| Спросить | Ответить (при вопросе агента) / Продолжить сессию | запуск |
| Отменить | Остановить | активный запуск |
| Commit · Push · Создать MR | Подготовить MR → форма → Создать MR | завершённая реализация |
| Удалить worktree | Удалить workspace | ⋯, danger |
| Убрать | Убрать из dashboard | ⋯, danger |
| worktree | workspace (рабочая копия агента) | везде в UI |
| runner / агент | агент | везде |
| Полный лог | Технический лог | запуск |

## 9. Что оставляем как есть

- Подсказки на действиях (сокращаем текст, принцип сохраняем).
- Подтверждения только для push, создания MR, удаления workspace с изменениями, удаления объекта из dashboard.
- Мгновенный переход на страницу запуска после клика; фоновые запуски; polling статуса.
- Отдельная страница doctor и CLI.
- Токены вместо долларов.
