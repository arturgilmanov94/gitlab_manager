## [0.7.0] — 2026-09-09

История MR и автоочистка списка, читаемые адреса, вердикт, согласованный с замечаниями.

### Добавлено
- **История** (`/history`): MR, которые вас больше не касаются — вы одобрили, вас сняли с ревью/assignee,
  MR влит или закрыт — уходят из основного списка сюда, если по ним были запуски; все действия ревью доступны
  как в основном списке. MR без запусков и без вашей роли убираются из dashboard при синхронизации. MR,
  добавленные по ссылке вручную, остаются, пока их не убрать самому. Синхронизация теперь обновляет и MR,
  которых GitLab больше не возвращает, и сообщает, сколько ушло в историю и сколько убрано.
- В строке MR бейджи «одобрен мной» и «без роли»; «Обновить из GitLab» в меню ⋯ строки.

### Изменено
- **Читаемые адреса**: `/-/review/12`, `/-/quick-review/13`, `/-/verify/14`, `/-/fix-comments/15`,
  `/-/task-plan/16`, `/-/task-implement/17`, `/-/mr/3`, `/-/issue/4`. Старые `/run/12`, `/mr/3`, `/issue/4`
  перенаправляют на новые.
- **Вердикт всегда согласован с замечаниями**: dashboard выводит его из открытых замечаний (CRITICAL → блокер,
  HIGH → нужны правки, остальное → ок с замечаниями, ничего → можно мерджить); «Ок с замечаниями» без единого
  замечания больше не бывает.
- **Описание MR обязательно**: схема результата требует осмысленный `summary` (что меняет MR и зачем, затем
  оценка), промпты ревью и проверки повторяют это требование.

## [0.6.0] — 2026-09-09

Интерфейс по дорожной карте: Обзор, Сессии, Workspaces, данные GitLab на MR, читаемый вывод агента.

### Добавлено
- **Обзор** — домашняя страница: «Нужно от меня» (нужен ответ агенту → упавший pipeline моего MR → новые коммиты
  после ревью → ошибки запусков → задачи, готовые к MR → MR, ещё не проверенные), у каждого пункта одно действие;
  «Агенты» (активные сессии с текущим шагом и таймером); «Мои MR» (счётчики: открытые, pipeline failed,
  с обсуждениями, одобрены). Список MR переехал на `/mrs`.
- **Сессии** (`/runs`): все запуски всех типов, активные сверху, действие по состоянию, фильтр.
- **Workspaces** (`/workspaces`): worktree дашборда с состоянием (агент работает · незакоммиченное · закоммичено,
  не отправлено · отправлено в origin), связанной сессией, копированием пути и удалением.
- **Данные GitLab на MR**: head pipeline (✓/✕/●), approvals n/m, отставание от целевой ветки, Draft, число файлов —
  в списке, в детали MR и в Обзоре. Синхронизация обновляет каждый MR отдельным запросом (диверсия и pipeline
  в списочном API отсутствуют).
- **Вывод агента как markdown**: summary, замечания, предлагаемые фиксы, план, отчёт и диалог рендерятся с
  inline-кодом, блоками кода, списками и ссылками; упоминания `путь/файл.php:строка` и колонка «Где» ведут в
  GitLab на проверенный коммит («Код ↗» в меню замечания).
- **Статусы замечаний вручную**: ⋯ у замечания → «Ложное срабатывание», «Игнорировать», «Отметить решённым»,
  «Вернуть в открытые»; такие замечания не считаются открытыми и не попадают в проверку изменений.
- **Контекст сессии**: «Проверить изменения» продолжает сессию агента, в которой делалось ревью (тот же
  runner), — контекст MR не собирается заново; на странице сессии видна цепочка «ревью → проверка» и подпись
  «Продолжение сессии #N».
- Фильтр по строкам в списках MR, задач и сессий (запоминается на вкладке).

### Изменено
- Запуск из списка или детали **не уводит на страницу сессии**: строка меняет состояние, можно сразу запустить
  следующий; сессия — по кнопке «Открыть прогресс».
- Курсор «вопрос» у подсказок убран; подсказка показывается как раньше.
- `RUN_CONCURRENCY` по умолчанию 4 (было 1).
- Технический лог: строка `[init]` сведена к сессии, модели, режиму прав и версии CLI вместо полного JSON;
  результат — коротко (полный JSON хранится с запуском); отказы — `[denied] инструмент: вызов`; в браузере
  строки лога подсвечены по типу (вызов инструмента, запрос разрешения, решение, отказ).

## [0.5.0] — 2026-09-09

Запросы разрешений агента видны и решаются в dashboard; Claude Code работает через потоковый протокол в своей песочнице.

### Добавлено
- **Разрешения из dashboard, как в терминале.** Claude Code запускается по потоковому протоколу
  (`--permission-prompt-tool stdio`): когда агенту нужно разрешение, сессия переходит в состояние
  ⚠ «Нужен ваш ответ», на странице сессии показан инструмент, ввод, причина и предложенные агентом правила;
  кнопки «Разрешить», «Разрешить и не спрашивать в этой сессии», «Отклонить» (с комментарием агенту).
  В шапке — бейдж с числом ожидающих ответов, в списках MR и задач — действие «Ответить агенту».
  Без ответа за `APPROVAL_TIMEOUT_SEC` (30 минут) запрос считается отклонённым. Запуски из CLI
  (`mr-review review`) спрашивают в терминале.
- **Режим прав `CLAUDE_PERMISSIONS=auto`** (по умолчанию): вместо ручных allow/deny-списков — классификатор
  Claude Code и его песочница (`autoAllowBashIfSandboxed`); read-only запуски получают корень проекта
  read-only для shell и по-прежнему не могут редактировать файлы; запись в GitLab и `git push`/`commit`
  запрещены явно. Агенту доступны субагенты, запись во временный каталог и сеть. `manual` — классический
  режим Claude Code (правила проекта, остальное спрашивается в dashboard); `strict` возвращает прежнее поведение.
- Сквозные проверки против настоящего Claude Code за build-тегом `e2e`
  (`go test -tags e2e -run TestE2E ./internal/runner`): схема результата по потоку, read-only корень проекта,
  субагенты, доставка и исполнение решений по запросам разрешений.
- На странице активной сессии видно, что агент делает сейчас (последний вызов инструмента); после
  завершения — таблица всех запросов разрешений с решениями и список вызовов, отклонённых автоматически.
- **Сохранить план в проект**: план исследования выгружается в markdown (`PLANS_DIR`, по умолчанию
  `<проект>/.claude/plans/<дата>-<задача>-run<N>.md`) — задача, суть, шаги, файлы, риски, вопросы, оценка;
  путь запоминается у сессии.

### Изменено
- Активные запуски: `queued`, `running` и новый `waiting`; перезапуск dashboard помечает ожидавшие ответа
  запросы как истёкшие.

## [0.4.0] — 2026-09-09

Dashboard — интерфейс поверх агентов проекта: каждое действие ищет свой skill в `.claude/` проекта.

### Добавлено
- **Карта «действие → skill проекта»** (`docs/SKILLS.md`). Каждое действие dashboard сначала ищет в `.claude/`
  проекта свой агент/команду/skill: `review_full` → `mr-review`, `review_quick` → `mr-review-quick`,
  `review_verify` → `mr-review-verify`, `fix_comments` → `mr-fix-comments`, `plan` → `task-plan`,
  `implement` → `task-implement`. Имена переопределяются `SKILL_*` в `.env` (`REVIEW_SKILL` остался алиасом).
  Быстрое ревью и проверка изменений без своего skill используют skill полного ревью; остальные действия без
  skill идут по CLAUDE.md / AGENTS.md и промпту dashboard. Агент подключается через `--agent`, команда/skill —
  slash-командой в промпте. Раньше skill проекта участвовал только в ревью.
- Doctor показывает строку `Skill: <действие>` на каждое действие (OK — свой skill, WARN — запасной или нет,
  FAIL — файл skill непригоден); на странице проверки окружения — таблица с ожидаемыми именами и тем, что должен
  делать каждый skill. `./mr-review skill` печатает ту же карту; идентификатор skill сохраняется у всех запусков.
- Тесты на параллельные запуски: при `RUN_CONCURRENCY>1` разные MR/задачи выполняются одновременно, один и тот
  же объект — никогда; создание worktree сериализовано замком на общий `.git`.

### Исправлено
- Worktree для «Исправить замечания» на ветке MR, которую этот чекаут никогда не фетчил, молча создавался
  от `origin/develop`. Теперь ветка сначала фетчится с origin и берётся оттуда.
- Запрошенный, но не найденный агент (`runner`) больше не подменяется случайным из доступных — возвращается ошибка.
- Тестовая фикстура работала только с git ≥ 2.28 (`git init -b`).

## [0.3.0] — 2026-09-08

Фаза D плана «engineering cockpit»: дизайн-система и контракт действий применены к существующим экранам.

### Изменено
- Действия зависят от состояния объекта. В строке MR одно главное действие: «Запустить ревью» (ещё не проверен),
  «Проверить изменения» (после ревью появились коммиты), «Открыть замечания / результаты» (проверен),
  «Открыть прогресс» (идёт проверка), «Посмотреть ошибку» + «Повторить» (ошибка). Рядом «GitLab ↗» и меню ⋯
  с остальным: быстрое ревью (только diff, экономит токены), полное ревью заново, история, копирование ссылки,
  остановить, убрать из dashboard. Недоступные пункты объясняют причину при наведении.
- Состояние AI-ревью показано отдельно от состояния GitLab: ○ Ещё не проверен · ● Проверяется · ✓ Проверен ·
  ⚠ Есть новые изменения · ✕ Ошибка, с текстом рядом со знаком; старый вердикт подписан коммитом, к которому относится.
- Задачи: человеческие состояния (Новая · Исследуется · Есть план · Пишется код · Готово к MR · Ошибка · Остановлено вами);
  главное действие «Решить задачу», рядом «Исследовать»; после исследования — «Реализовать этот план»,
  план автоматически передаётся агенту; после реализации — «Подготовить MR».
- Страница сессии: человекочитаемая ошибка с «Повторить» и «Технический лог» вместо stacktrace; блок «Контекст
  сессии»; workspace-действия с меню ⋯ для удаления; «Продолжить сессию с агентом» вместо «Спросить».
- Переименования: «Быстрое/Полное/Проверить» → см. выше; «План» → «Исследовать»; «Реализовать…» → «Решить задачу»;
  «Отменить» → «Остановить»; «Полный лог» → «Технический лог»; worktree → workspace.
- Новый визуальный стиль: спокойная светлая шапка, плотная типографика, карточки состояний, единые бейджи и кнопки.
  Адаптивность: на ширине до 1100 px таблицы становятся карточками, до 820 px перестраиваются шапка и панели.
- Doctor перенесён в подвал; выбор агента — в панели инструментов и на страницах объектов.

### Добавлено
- «Повторить» для любого завершившегося запуска (`POST /api/runs/{id}/retry`) — тот же запуск с теми же параметрами.
- Сообщения-подтверждения после клика («Ревью поставлено в очередь», «Создаю workspace»); позиция прокрутки
  сохраняется при обновлении страницы.

## [0.2.1] — 2026-09-08

### Изменено
- Вместо стоимости в долларах везде показываются **токены**: в истории запусков, на странице запуска, у ответов
  агента и в подвале (сумма за всё время). При наведении — разбивка: вход, выход, чтение кэша, запись кэша.
  Считаются суммарно по всем моделям запуска (агент и его субагенты). Причина: при работе по подписке
  важны лимиты в токенах, а доллары были лишь расчётной ценой по API-прайсу.
- Для старых запусков токены дозаполняются из сохранённого результата при старте сервера.

### Исправлено
- Тесты на CI: коммит в worktree требовал git identity, которой нет на runner'ах GitHub.



Переписано с Python на Go: один статический бинарник для Linux вместо venv, uv и bootstrap-скрипта.

### Добавлено
- Вкладка **Задачи**: синхронизация задач GitLab (assignee = вы) и добавление по ссылке; **План** (read-only анализ:
  шаги, файлы, риски, вопросы, оценка) и **Реализовать** в отдельном git worktree на ветке от `origin/develop`
  с именем по ссылке на задачу; Commit, Push и Создать MR отдельными кнопками с подтверждением.
- **Исправить замечания ревьюеров** для своих MR с нерешёнными обсуждениями: worktree на ветке MR, агент правит
  код по комментариям, push обновляет MR. Счётчик нерешённых обсуждений и бейдж «мой» в списке MR.
- **Быстрое ревью** как лёгкий вариант рядом с полным; проверка исправлений (verify) работает от любого из них.
- Выбор агента на запуск: Claude Code, Codex CLI, Cursor CLI (показываются только найденные в PATH).
- **Вопрос агенту**: продолжение той же сессии агента по результату запуска, история сообщений сохраняется.
- Подробные подсказки при наведении на каждую кнопку: что произойдёт, где, что не будет тронуто.
- Определение проекта по единственному соседнему git-репозиторию с инструкциями для агентов
  (`CLAUDE.md`, `AGENTS.md`, `.claude/CLAUDE.md`, `.claude/{agents,commands,skills,rules}`); при нескольких
  кандидатах doctor перечисляет готовые команды.
- Запуск без аргументов поднимает сервер и открывает браузер (пригодно для двойного клика); `install-desktop.sh`
  ставит ярлык в меню приложений.
- `GITLAB_PROJECT` для случаев, когда origin remote не разбирается.
- Понятное сообщение, если порт занят другим экземпляром mr-review.

### Изменено
- Интерфейс на русском, стиль ближе к GitLab: шапка, вкладки, бейджи, состояния запусков (спиннер, очередь,
  завершён, не вышло, отменён), индикатор прогресса с таймером.
- Все запуски (ревью, проверка, план, реализация, исправление) хранятся в одной таблице `runs`; findings и
  обсуждения привязаны к запуску.
- Логи запусков — `logs/runs/run-<id>.log`, лог сервера — `logs/server.log`.

### Удалено
- Выбор модели в интерфейсе: за модель отвечают правила и агенты самого проекта.
- Python-версия (0.1.0) и её bootstrap/uv-инфраструктура.

## [0.1.0] — 2026-09-08

Первая версия на Python (FastAPI, uvicorn, Jinja2, SQLite).

### Добавлено
- Список MR с синхронизацией из GitLab через `glab` (reviewer/assignee) и добавлением по ссылке.
- Полное ревью через `claude -p --agent mr-review` из корня проекта с JSON-схемой результата; findings с
  severity, файлом, строкой и предложением фикса; оценка нерешённых обсуждений.
- Проверка исправлений: статусы fixed / open / obsolete для прежних findings плюс новые проблемы.
- Обнаружение review-скилла проекта (`ReviewSkillResolver`) без копирования; определение project root
  через `PROJECT_ROOT`, git и родительские каталоги.
- Doctor, лаунчер `./mr-review`, `bootstrap.sh`, release-архив с проверкой на абсолютные пути и секреты.
