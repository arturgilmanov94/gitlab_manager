## [0.21.1] — 2026-09-11

### Изменено
- **Возврат к спискам.** На страницах MR, задачи и сессии первая крошка стала кнопкой «← назад». Она ведёт туда,
  откуда вы пришли (список с вашими фильтрами, обзор, страница MR или задачи для сессии), иначе — в список по
  умолчанию. Клавиша Esc делает то же, если фокус не в поле ввода и не открыто меню. У сессии в крошках появилась
  ссылка «Сессии».
- **«Просмотрено» на странице MR** — кнопка в шапке рядом с основным действием (раньше только в списке и в
  меню ⋯). После отметки возвращает к списку; у отмеченного MR в шапке бейдж и кнопка «Снять отметку».

## [0.21.0] — 2026-09-11

### Добавлено
- **Процент контекста сессии.** В фактах запуска (страница сессии, блоки AI review на MR и задаче) появился
  «контекст N%»: заполнение контекстного окна агента на последнем ходе основной сессии по данным Claude Code

  Ходы субагентов не учитываются. Только для сессий, начатых с этой версии; Codex и Cursor не сообщают контекст.

### Изменено
- Миграция `017_run_context`: у запусков колонки `context_tokens` и `context_window`.

## [0.20.0] — 2026-09-11

## [0.19.0] — 2026-09-11

Ускорение ревью без изменения skills проекта.

### Изменено
- **Ревью идёт в read-only worktree на точном head SHA MR** (`runtime/worktrees/review/<проект>-<iid>`), а не из корня
  проекта с вашей текущей веткой: агент читает файлы MR напрямую через Read/Grep вместо запросов к GitLab и не путает
  их с рабочей копией. Worktree переиспользуется и переезжает на новый head; запись туда запрещена песочницей.
  Если head недоступен, запуск идёт из корня проекта, о чём написано в техническом логе. Настройка `REVIEW_WORKTREE`.
  То же для «Проверить замечание» и «Разобрать ошибки CI». Контекст сессий ревью теперь привязан к этому каталогу:
  сессии ревью, сделанные до 0.19.0 из корня проекта, для продолжения не предлагаются.
- **Предзагрузка контекста.** Dashboard сам получает из GitLab список изменённых файлов, diff MR и нерешённые
  обсуждения и кладёт их в промпт: агент пропускает первую серию вызовов инструментов. Diff вставляется до
  `PREFETCH_MAX_DIFF_CHARS` символов (по умолчанию 60000), иначе остаётся список файлов. Кэшируется по head SHA.

## [0.18.0] — 2026-09-11

Phase 7 плана: исправление выбранных замечаний.

### Добавлено
- **Исправить выбранные.** На странице своего MR у открытых замечаний AI-ревью и у нерешённых обсуждений ревьюеров появились
  чекбоксы (и «выбрать все»). Панель выбора показывает число и поле указаний; «Исправить выбранные» запускает агента в
  workspace ветки MR. Агент перепроверяет каждое замечание, не считая его верным априори, исправляет подтверждённые,
  учитывает выбранные обсуждения, прогоняет тесты и делает self-review. По каждому замечанию итог: исправлено ·
  не подтверждено · пропущено — он записывается на само замечание (исправленные закрываются со ссылкой на сессию,
  неподтверждённые остаются открытыми с пометкой). Далее обычные Commit / Push и «Проверить изменения».
  Только для своих MR. Новое действие в карте skills: `fix_findings` → `mr-fix-findings` (`SKILL_FIX_FINDINGS`),
  без него используется skill исправления замечаний ревьюеров.

### Изменено
- Миграция `015_run_selection`: у запусков колонка `selection_json`.

## [0.17.0] — 2026-09-11

Phase 6 плана: CI.

### Добавлено
- **Экран «CI»** (вкладка с красным счётчиком): MR основного списка с упавшим head pipeline, их упавшие jobs (стадия,
  причина, allowed to fail, ссылки), состояние разбора и действия. Пусто — «Нет известных упавших pipeline».
- **Разобрать ошибки CI** — read-only запуск: агент получает упавшие jobs и хвосты их логов (200 строк, без ANSI-кодов),
  сопоставляет с diff MR и кодом и по каждому job говорит тип (код MR · тест · флак · инфраструктура · конфиг), причину с
  доказательствами, исправление и можно ли исправить в MR. Страница сессии показывает таблицу и «Исправить CI».
- **Исправить CI** — только для своих MR: агент в workspace ветки MR исправляет причины падения, прогоняет относящиеся
  тесты, делает self-review; что исправить в MR нельзя — перечисляет с причиной. Разбор, если был, передаётся ему.
  Далее обычные Commit / Push (push обновляет MR и перезапускает pipeline).
- На странице MR карточка «Pipeline failed» с jobs и хвостами логов; в Обзоре элемент «Pipeline failed» ведёт на экран CI.
- Новые действия в карте skills: `ci_analyze` → `mr-ci-analyze`, `ci_fix` → `mr-ci-fix`.

### Изменено
- Синхронизация сохраняет id и ссылку head pipeline (миграция `014_mr_pipeline`).

## [0.16.0] — 2026-09-10

Phase 5 плана: задачи.

### Добавлено
- **Разбор бага** внутри «Исследовать». На странице задачи переключатель «Исследовать как: Задачу · План / Баг · root cause»;
  для задач с меткой или названием про баг (bug, fix, ошибка, падает…) режим бага выбран заранее. Результат: ожидалось /
  фактически, воспроизведение, путь выполнения, root cause с доказательствами, предлагаемое исправление, риски, оценка.
  Кнопка «Исправить» передаёт root cause и предложение агенту в отдельный workspace. Код при разборе не меняется.
- **«Решить задачу» как многофазный сценарий** в одной сессии: план → реализация → тесты → self-review диффа → отчёт.
  В отчёте новое поле `self_review`, этапы видны в цепочке этапов сессии.
- **«Довести до MR»** на странице реализации: чек-лист (реализация · тесты · self-review · чистый diff · push) и форма MR
  с заголовком и описанием, собранным из отчёта агента (что сделано, проверки, известные ограничения, self-review).
  Кнопка «Создать MR» активна только после Push; создание подтверждается. Диалоги prompt() убраны.

### Исправлено
- Слинкованные в workspace файлы инструкций (`.claude`, `CLAUDE.md`, `AGENTS.md`) попадали в `git status` и в коммит по
  кнопке Commit как симлинки с локальным путём. Теперь status, diff и commit исключают их через pathspec; конфиг и
  `info/exclude` репозитория не трогаются.
- «Ветка запушена» определялось по любому upstream: свежая ветка отслеживала `origin/develop` и считалась отправленной.
  Теперь проверяется именно `origin/<ветка>`.

### Изменено
- Миграция `013_run_mode`: у запусков колонка `mode` (для plan: `bug`).

## [0.15.0] — 2026-09-10

Phase 4 плана закрыта: структурные этапы вместо «последнего вызова».

### Добавлено
- **Этапы сессии.** Каждый вызов инструмента агента сохраняется (таблица `run_events`) и относится к этапу: Подготовка

## [0.14.0] — 2026-09-10

Phase 4 плана, часть «Нужен ваш ответ по существу».

### Добавлено
- **Агент задаёт вопросы вместо угадывания.** В исследовании, решении задачи, исправлении замечаний и проверке на стенде
  агент может остановиться со списком вопросов (`ask`: вопрос, варианты, почему это важно). Сессия переходит в состояние
  «Нужен ваш ответ», на странице сессии появляется форма: вариант или свой текст на каждый вопрос, «Ответить и продолжить».
  Ответы уходят в **ту же** сессию агента (`--resume`), работа продолжается и завершается обычным результатом. Вопросы
  и ответы сохраняются на странице сессии; токены и время считаются суммарно по этапам. Такие сессии видны в шапке
  («Нужен ваш ответ»), в Обзоре и в строках задач и MR; перезапуск dashboard их не теряет, «Остановить» работает.
  Если агент не вернул идентификатор сессии, запуск завершается ошибкой с объяснением.

### Изменено
- Схемы результатов `plan`, `implement`, `fix_comments`, `stand_test` получили поле `ask`; правило «не угадывай — спроси»

## [0.10.0] — 2026-09-10

Phase 2 плана закрыта: MR как эталон.

### Добавлено
- **«Проверить замечание»** — отдельный read-only мини-запуск по одному замечанию (меню ⋯ у открытого замечания на
  странице MR или сессии). Агент не считает замечание верным априори и выносит решение: подтверждено · ложное
  срабатывание · неактуально · недостаточно данных, с доказательством из кода и, при необходимости, уточнённой severity
  и фиксом. Ложное и неактуальное закрывают замечание, подтверждённое остаётся открытым; итог и ссылка на проверку
  показаны прямо в строке замечания. Несколько проверок по одному MR могут идти параллельно; проверки не влияют на
  состояние AI-ревью MR в списке. Новое действие в карте skills: `verify_finding` → `mr-verify-finding`
  (`SKILL_VERIFY_FINDING`), без своего skill используется skill полного ревью.
- **«Что изменилось» после ревью.** Если после ревью появились коммиты, бейдж на странице MR показывает число коммитов,
  файлов и строк `+/−` между проверенным SHA и текущим head (compare API GitLab, результат кэшируется).

### Изменено
- Миграция `009_finding_check`: у замечаний `check_status` и `check_run_id`, у запусков `finding_id`.

## [0.9.0] — 2026-09-10

Phase C плана: контекст сессии агента виден и выбирается до запуска.

### Добавлено
- **Выбор контекста перед запуском.** На страницах MR и задачи рядом с выбором агента появился список «Контекст»:
  «Новый чат · пустой контекст» (по умолчанию) или «Продолжить сессию #N · тип · агент · токены · когда». Продолжение —
  `--resume` той же сессии агента: он помнит объект и прежние результаты. Предлагаются только подходящие сессии:
  завершённые, с сохранённым идентификатором, того же каталога (ревью и исследование — корень проекта, решение задачи —
  workspace ветки). Сессия продолжается тем же агентом, выбор агента при этом игнорируется. Сессия другого действия
  отклоняется с объяснением ещё в браузере. «Повторить» сохраняет выбранный контекст.
- В строке MR и задачи бейдж «контекст #N» — есть сессия агента, которую можно продолжить; ведёт к выбору контекста.
- Страница «Сессии»: запуски одной сессии агента показаны цепочкой «сессия: #1 → #5» в строке каждого из них.
- Страница сессии называет выбранный контекст сразу после старта, не дожидаясь завершения запуска
  («по вашему выбору агент продолжает контекст «Полное ревью» (1,2M токенов, сессия #1)»).
- Промпт продолженного запуска начинается с пометки, что это новая задача в той же беседе: переиспользовать
  изученное, перечитывать только изменившееся.

### Изменено
- `runs` получили колонку `continue_run_id` (миграция `008_runs_continue`). API запуска принимает `continue_run`.

- Логи запусков — `logs/runs/run-<id>.log`, лог сервера — `logs/server.log`.

### Удалено
- Выбор модели в интерфейсе: за модель отвечают правила и агенты самого проекта.
- Python-версия (0.1.0) и её bootstrap/uv-инфраструктура.
